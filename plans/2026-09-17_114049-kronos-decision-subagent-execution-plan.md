## 1. 执行方式：子代理做有限实现，主模型决定能否过关

### 1.1 分工

| 角色 | 必须负责 | 不允许自行决定 |
| --- | --- | --- |
| 主模型/主控 | 用户授权、基线、契约、文件租约、派发、集成、真实验证、阶段判定、变更取舍 | 不得把子代理“完成”当作验收通过，不得绕过数据与研究审批 |
| 实现子代理 | 读取指定输入，修改白名单文件，运行局部验证，回传证据与限制 | 不扩大架构、依赖、文件、数据、外部调用和测试政策 |
| 研究子代理 | 执行已冻结的短批研究或分析已完成的真实产物 | 不窥看锁定测试集调参，不改门槛追求好结果 |
| 临时只读审阅子代理 | 对指定高风险点提出缺陷和源码证据 | 不代替主模型最终验收，不直接修改实现 |

角色是任务能力标签，不是永久保持运行的“专家团队”。默认每个任务新建短上下文；不把所有阶段交给同一个长会话。

### 1.2 主控必须执行的循环

1. 检查前驱是否已通过，以及本阶段授权是否覆盖该任务。
2. 读取当前实际文件与差异；冻结输入契约、基线标识、写文件白名单和验证范围。
3. 派发一个 SA 任务；仅在第 3 节允许的批次派发两个独立任务。
4. 子代理先局部自测，返回实际路径、命令、退出码、证据和限制。
5. 主模型检查差异、越界改动和测试有效性；亲自运行任务卡指定的核心验证。
6. 主模型按状态判定：通过、返工、阻塞或部分完成；不是仅转述子代理摘要。
7. 当前批集成并通过所需检查后，才能解除文件租约、派发依赖任务。
8. 到阶段出口时执行跨模块验收，不用单项测试拼凑成未经运行的完整闭环。

阶段启动前冻结必选验收项、版本与范围。删除必选项必须显式记录为范围变更并由主控核准；涉及产品能力或风险边界时重新取得用户确认。不能在失败后缩小清单，再把原阶段改成通过。

主模型可以执行必要的薄集成修改，但如果变成新功能、大范围返修或契约变化，应形成新的受限补充任务，并重新验收受影响范围。

### 1.3 不采用的默认流程

- 不固定每任务双审、不机械全量 TDD、不按每个函数建立永久测试。
- 不每任务自动 commit，不创建 PR、推送、发布或部署。
- 不以“子代理可以并行”为理由同时修改共享文件。
- 不编造每项几分钟或整个项目几天完成；以短交付单元和证据推进。
- 不通过删除测试、放宽断言、默认 skip 或模拟行情来伪造完成。

## 2. 派发前总闸门 PRE0（主模型执行）

PRE0 是首次实施前的主控工作，不委派一个有写权限的代理去自行决定项目位置。

### 2.1 必须确定

- 实际本地项目绝对路径；不存在时，先明确克隆目标和授权，不能假定历史机器路径仍有效。
- 仓库 `AGENTS.md`、当前分支、HEAD、已修改/未跟踪文件及用户在做的工作。
- Python/Conda 实际环境、启动方式、可用 CPU/GPU、磁盘及网络限制。
- 当前依赖源、测试入口、配置/行情/模型/持仓目录。
- 本次授权到哪个阶段；默认建议先实施 M0，不把规划批准视为所有后续真实操作批准。
- 每任务独立临时目录与证据目录，不将个人数据、缓存、实验大文件加入版本库。

### 2.2 只读基线命令

以下从已确认项目根目录运行，属于实施时的命令，本轮未运行：

```bash
git status --short
git rev-parse HEAD
git diff --stat
python --version
python -m pip --version
```

不要在环境未知时自动安装依赖；不要在 SA01 完成前运行原始全量测试。真实配置与用户数据的保护检查只覆盖本项目相关路径，不扫描或收集整个用户目录。

### 2.3 输入契约和所有权约定

- 每个任务接收准确的仓库根目录、基线与未提交差异标识；只有 commit ID 不足以标识有用户改动的工作区。
- 任务返回文件前后差异及证据清单。主控合并时保护用户原改动，禁止 `reset --hard`、强制 checkout、整目录覆盖或清空缓存。
- 本计划列出的新模块/测试路径均是“目标路径”；实施前核查现有等价实现，能复用则经主控记录映射后复用，不制造空模块。
- `AGENTS.md`、依赖清单/锁文件、`conftest.py`、共享契约、`webui/app.py`、`decision/engine.py` 默认单写者；仅在对应任务被明确授予独占租约时允许子代理修改。
- 路径所有权包含测试夹具、运行目录和 SQLite 文件；不同任务使用不同测试数据库与临时根目录。
- 并行时主控不同时改子代理正在写的文件，不执行会修改公共配置的集成操作；环境安装/迁移属于全局独占操作。

- 上表是默认排期，不是强制等待所有无关事项的全局串行锁。主控可在前驱已通过、文件已解锁且不越过阶段安全出口时重排独立任务，记录原因；不能让子代理自行抢跑。

- **主模型验收：** 在确认收集安全后执行 `python -m pytest tests --collect-only -q`，再执行 `python -m pytest tests -m "not live_data and not model_inference and not slow"`；核对目标配置和用户数据前后不变，确认默认测试无网络/GPU加载。
- **交付：** 隔离实现、真实基线失败列表、实际命令与退出码。旧缺陷单独列出，不要求靠弱化断言变绿。

- **失败边界：** 未证明导入阶段安全，不运行全套测试；缺依赖先报告，不自动安装。

### SA02：最小报告契约及后端拒绝动作

## 5. 主模型独立验收的具体规则

### 5.1 每个 SA 回来都必须检查

1. **范围：** 实际改动是否在白名单内，是否改坏用户原修改、引入依赖或隐式安装。
2. **行为：** 检查入口和消费者，不只看单个函数；新状态是否真正传到页面和存储。
3. **测试：** 预期是否独立，是否删弱旧断言，是否通过 Mock 返回固定值掩盖真实路径，是否大面积 skip。
4. **亲自运行：** 用主模型工具重跑任务卡指定的关键命令和反例；记录真实退出码、收集/执行/跳过情况。
5. **必要集成：** 涉及浏览器、进程、CSV/SQLite 或模型时，按任务要求穿过真实边界。构建或导入成功不能替代。
6. **副作用：** 相关用户配置/数据不变，临时进程和文件按批准范围清理，无真实外部写入。
7. **判定：** 必需项没有足够证据就不通过；子代理自评只作为线索。

项目要求 LSP 诊断时使用实际可用工具；若不可用，明确记为未运行，并执行已锁定的等价静态/类型与原生检查，不编造 LSP 通过。

### 5.2 状态台账

任务状态使用 `NOT_STARTED / READY / RUNNING / READY_FOR_ACCEPTANCE / ACCEPTED / REWORK / BLOCKED / PARTIAL / DEFERRED`。只有主控可以设为 ACCEPTED。

验收项状态单独使用“已验证 / 部分验证 / 未验证 / 不适用”。实验执行状态另列“未运行 / 运行中 / 完成 / 失败 / 无效”；只有完整且有效的实验才给出“支持增益 / 不支持增益 / 证据不足”等科学结论。未运行或只跑小样例不能改名为“证据不足”后宣布评估完成。策略资格另列 RESEARCH/SHADOW/ELIGIBLE/SUSPENDED/RETIRED，各状态互不替代。

| 字段 | 必须记录 |
| --- | --- |
| 任务与基线 | SA 编号、任务版本、前驱、仓库路径、基线和用户差异 |
| 租约与执行 | 子代理 ID、写范围、开始/结束、实际进度 |
| 子代理证据 | 文件、命令/退出码、数据/模型/实验 ID、替身清单、测试变更账、限制 |
| 主模型验收 | 独立执行命令、实际输出/产物、逐项状态 |
| 资格与缺口 | 外部审批、数据缺口、未成熟样本、被禁能力 |
| 后续 | 返工范围或可释放的依赖，不写模糊“继续完善” |

已 ACCEPTED 的文件被后续任务改动时，主控重跑受影响的旧验收；旧通过记录保留，但当前版本对应的证据必须更新。台账用“任务 ID + 子项/交付版本 + 契约版本”区分 SA09.current/history 和早期恢复验收；部分通过只释放该子项的明确消费者，不传播为整个任务通过。

### 5.3 阶段出口的额外检查

- **G0：** 真正拒绝旧页面/旧 API 绕行，而不是只测新函数。
- **G1：** 主源失败、备源成功、陈旧缓存以及未知证券状态分别展示，数据新鲜度不能来自文件时间。
- **G2：** 主控亲自使用真实输入穿过 API→存储→页面，并重启读回；纯 Mock 不允许过关。
- **G3：** 冻结协议、真实历史输入、账本和完整结果共同成立；样例回测成功不代表真实实验完成。
- **G4：** 样本真实、任务受控和模型价值是三个判定；不能因为真实模型能运行就声称有投资价值。
- **G5E：** 测试资格仅在测试环境存在；真实策略仍按已有前瞻状态运行。
- **G5Q：** 主模型检查成熟样本、全部失败/排除记录和既定门槛；不得因模型“很有信心”绕过证据。

## 6. 长实验与前瞻任务：不让一个子代理无限挂起

### 6.1 SA20/SA27 长实验

1. 子代理生成冻结的运行清单、预算与短批验证，不未经批准展开全池全时期。
2. 短批可在当前任务内完成；超出单任务预算时回传检查点，不继续无界扩大。
3. 需要持久运行时，由主控在授权资源/网络范围内启动可追踪的后台进程并启用结束通知；记录运行 ID、命令、源/数据版本和产物目录。
4. 长实验从冻结的研究运行副本/输入执行；未具备隔离时，不并行修改实验会读取的源码、配置或数据。创建工作副本不得冒用 Git 提交/分支授权。
5. 完成后用新的短子任务读取真实产物做分析；主控复跑选定分段、核对总数和日志，再判定 SA20/SA27。
6. 进程还在运行但没有新日志/产物，与有真实推进分开汇报；不要把子代理退出当实验成功。

## 8. 返工、冲突和停止规则

### 8.1 返工

- 首次不通过：主控给出准确反例、失败命令、允许修复文件和不应改变的行为，建立 `SAxx-r1`，不把整个阶段推回重做。
- 同一路径连续失败两次：分类为代码/环境/权限/数据/工具问题，换证据路径或报告阻塞，不无界重试。
- 修改契约：暂停受影响任务，评估兼容性；必要时向用户确认真实范围变化，冻结新版本后重跑消费者验收。
- 子代理摘要与实际产物不一致：以主控核验为准，不接受“工具应该成功了”。

### 8.2 文件冲突

- 不并发覆盖同一文件，不靠事后自动合并解决未知契约冲突。
- 发现越界改动时停止该写入者、保留差异，主控核对是否涉及用户修改。
- 如果确需两个任务修改共享文件，改为串行或先由主控冻结契约；不要用创建分支/提交绕过授权。
- 根级依赖、测试配置、数据库迁移统一安排独占窗口。

### 8.3 安全边界

- 测试允许构造故障样例，但它们不能作为市场业绩、模型输出或真实前瞻的证据。
- 所有资金/账户/生产数据/真实外部写入继续禁止，除非有明确的独立授权；项目始终不自动下单。
- 发布/推送/安装服务/调度/外部 LLM/数据采购各自有审批边界，阶段通过不等于这些操作获准。
- 回退先保护配置、行情快照、持仓与 SQLite；不能宣称回退代码就恢复不兼容的数据 schema。
