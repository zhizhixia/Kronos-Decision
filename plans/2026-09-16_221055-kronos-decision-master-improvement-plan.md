## 0. 一页决策摘要

### 0.1 已确认的方向

1. 收盘后使用，以未来 5～20 个交易日为研究范围。
2. 服务于选股研究和已有持仓辅助，不做盘中短线信号器。
3. 保留现有工程，重构数据、决策与验证核心。
4. 先建立可信证据链，再考虑预测能力和功能扩张。

### 0.2 本计划推荐的产品边界

- 首期以沪深 A 股、自选股和沪深 300 范围为主；板块规则、证券状态或历史样本不完整的标的不开放动作参考。
- 研究周期固定为 5、10、20 个交易日；建议先以 10 日为主研究目标，其余为辅助目标，不根据测试结果临时切换主指标。
- 默认不接入真实账户；持仓和现金由用户手工录入或导入本地 CSV。
- 输出事实、排序、风险、反对证据、失效条件和复盘结果；不承诺收益。
- 只有通过适用范围内验证的策略，才有资格输出条件化交易参考；持仓数据不完整时不输出持仓数量或减仓比例。

### 0.3 不做什么

首期不做：券商接入、自动交易、分钟级择时、融资融券、衍生品、全市场无限制扫描、自动搜索海量策略、多智能体自动选股、重写前端框架、微服务化、分布式训练平台。

代码、论文和模型名称不构成策略有效性的证明。系统允许得出“没有增量价值”或者“证据不足”的结论。

### 0.4 推荐推进顺序

`M0 安全与验证基线 → M1 可信数据 → M2 最小可追溯报告 → M3 真实研究基线 → M4 Kronos 增量验证 → M5 日常辅助与前瞻运行`

财务和公告分析列为 M6 后续扩展，不阻塞基本工程闭环，但也不能在未实现时宣传已有事件风险覆盖。

## 2. 用户可观察的最终结果

### 2.1 盘后使用流程

1. 打开首页，看到最近一次完整收盘数据日期、更新时间和任务状态。
2. 更新行情；遇到数据源失败时，明确看到失败源、备源状态和是否只能看历史数据。
3. 查看市场概览和自选股；默认展示研究结论，而不是满屏买卖按钮。
4. 打开个股报告：事实、同池排序、模型观点、风险、反对证据和失效条件分开显示。
5. 有持仓时，查看可用现金、可卖数量、集中度和用户风险约束是否被触发。
6. 选择保存观察记录；系统后续按原预测周期复盘，不覆盖旧报告。
7. 在验证中心查看策略资格、适用范围、近期失效提示和历史证据。

### 2.2 核心页面

- **盘后总览：** 最近完整交易日、数据覆盖、更新失败、任务进度、市场事实。
- **自选与候选：** 研究排序、证据状态、纳入原因和排除原因；不把研究分数称为胜率。
- **个股报告：** 当前事实、5/10/20 日研究结论、真实模型情景、证据与限制。
- **持仓与风险：** 手工持仓、现金、日期、集中度、约束冲突；不接账户。
- **研究与验证：** 基线对比、费用假设、样本范围、样本外结果、资格版本。
- **历史与复盘：** 原始报告、当时可见数据、随后实际表现、版本变更。
- **设置与诊断：** 环境、模型、数据源、工作目录、任务队列、日志和安全导出。

### 2.3 何时不提供动作参考

以下是系统职责，不是可被模型或 LLM 覆盖的提示：

- 数据无效、过期或当日日线未完成；
- 当前策略、模型版本或证券范围未获验证资格；
- 必需证券状态、公司行动或交易规则不完整；
- 策略依赖概率，但其校准证据不足或失效；
- 用户持仓、风险预算等行动所需上下文缺失；
- 模型超时、取消、输出异常，或关键运行结果尚未提交；
- 预计优势不满足已冻结的成本和风险政策；
- 当前市场偏移导致资格被暂停。

失败时返回原因和可恢复步骤。不得把未知、失败、缺失信号自动显示为 HOLD。

## 3. 目标架构与模块边界

```text
AKShare / BaoStock / 已存快照 / 合规导入
                 ↓
字段与单位适配 → 日历与证券状态 → 数据质量门禁
                 ↓
       不可变数据快照与可用性清单
                 ↓
       简单基线 / Kronos 真实样本
                 ↓
         策略证据与适用范围查询
                 ↓
       用户持仓约束与行动资格检查
                 ↓
     结构化报告 → 持久化 → 页面展示
                 ↓
        实际结果归档与前瞻复盘

离线研究：同一快照、同一策略语义、独立成交仿真
                → 滚动样本外证据
                → 受控策略资格注册
```

### 3.1 运行部署

- 日常应用仍是单机模块化单体；默认只监听本机。
- 推理进程统一拥有模型与 GPU，先限制为单模型任务顺序执行。
- Web 请求提交任务后返回任务 ID；页面查询实际进度，不把轮询进度当新结果。
- 不引入 Redis、Celery、Kubernetes 等组件作为首期前提。
- 研究环境不运行在用户点击报告的请求线程中；批量实验不得阻塞日常报告。
- 同一份策略实现可用于历史评估与盘后报告，但数据读取与成交仿真分别受控。

### 3.2 拟新增的职责模块

### 3.3 拟议 API 边界

以下为新版本目标路由，不是当前可调用接口。M2 冻结报告契约，M4 完成异步任务接口；不得提前在文档中描述为已上线。

| 接口 | 行为与边界 |
| --- | --- |
| `POST /api/v2/analysis-jobs` | 传入证券、周期、截止时点和模式；通过校验后返回 202 与任务 ID，不把受理当作分析成功 |
| `GET /api/v2/jobs/{job_id}` | 返回任务状态、阶段、实际进度和终态结果 ID；未知任务不伪造空报告 |
| `POST /api/v2/jobs/{job_id}/cancel` | 请求取消；已完成任务不回写成取消，运行中任务必须禁止晚到结果发布 |
| `GET /api/v2/reports/{report_id}` | 读取已保存报告，包含 schema 版本、全部时点和资格状态，不重新运行模型 |
| `GET /api/v2/data-status` | 返回数据源、最后完整交易日、快照质量与缓存状态 |
| `GET /api/v2/strategies/{strategy_id}/qualification` | 返回具体版本与范围的资格；前端不可修改或绕过 |
| `POST /api/v2/portfolio-snapshots` | 创建经预览确认的新持仓快照，不覆盖旧记录，不调用券商 |
| `PUT /api/v2/config` | 带预期配置版本提交完整变更；版本冲突拒绝，不能静默覆盖并发修改 |
| `GET /api/v2/health` | 区分应用存活、存储、数据与模型就绪；不泄露凭据或任意本地路径 |

- 证券、周期、模型、路径均用服务端允许值校验；用户不能传任意模型地址或数据 URL 触发加载。
- 所有状态修改接口采用适合本地应用的访问保护、Origin/Host 检查及必要的 CSRF 防护；仅绑定回环地址不被当成完整权限控制。
- 使用请求 ID 和提交幂等键；任务去重同时考虑数据快照、配置、模型和参数，不能跨版本复用结果。
- 旧接口进入明确的兼容/弃用周期；不再暴露旧模拟结果为正式报告。新客户端只消费新契约，旧页面同时修改，不能靠后端增加字段期望旧页面自动安全。

## 4. 必须先稳定的数据契约

### 4.1 统一时间语义

全系统以 `Asia/Shanghai` 解释市场日期，并区分：

- `event_time`：行情或公司事件对应的时间；
- `published_at`：外部信息首次披露时间，适用于公告和财务；
- `available_at`：研究系统在模拟决策时允许使用该记录的最早时间；
- `fetched_at`：本次实际抓取时间；
- `decision_as_of`：策略只允许观察到的截止时点；
- `generated_at`：报告生成时间。

收盘后的具体更新时刻不硬编码成“到了某个钟点必然完整”。完整性由交易日历、行情状态和数据源更新证据共同判断。市场级最后完整交易日与个股因停牌而缺失交易记录应分别处理。

预测周期按交易所交易日推进；个股停牌不应偷偷改变所研究的时间终点。目标日无可用估值时按协议标为不可评价或延期观察，不能填成预测价。

### 4.2 核心对象

| 对象 | 最低必要字段 | 关键不变量 |
| --- | --- | --- |
| `MarketSnapshot` | ID、证券、交易所、频率、时间范围、最后完整交易日、来源、复权、单位、内容哈希、质量结果 | 快照不可原地修改；修订产生新 ID |
| `UniverseSnapshot` | ID、股票池定义、生效区间、成分、获取时间、是否历史时点数据 | 当前成分股不能冒充过去成分股 |
| `InstrumentState` | 证券状态、板块、停牌、风险警示、上市退市日期、适用规则版本、可用时间 | 未知不等于正常；规则缺失不得开放相关动作 |
| `ForecastArtifact` | 输入快照、目标日期、模型与 tokenizer revision、参数、种子、样本/汇总、有效性结果 | 真实模型采样与合成测试数据严格分开 |
| `StrategySpec` | 策略版本、目标周期、股票池、特征、决策时点、持有/退出语义、风险约束 | 研究和盘后应用引用同一版本 |
| `EvaluationProtocol` | 主指标、时间切分、成本、基准、试验预算、资格标准、数据来源等级 | 测试集解封前冻结，不按结果更换目标 |
| `ValidationEvidence` | 协议、数据与模型版本、样本外结果、适用范围、限制、有效期/复核条件 | 资格不得跨版本、跨范围自动继承 |
| `PortfolioSnapshot` | 记录时点、现金、数量、可卖数量、成本口径、账户限制、数据来源 | 过期或不完整持仓不能生成数量建议 |
| `DecisionReport` | 报告版本、运行状态、证据状态、行动权限、原因、事实、观点、限制、所有上游 ID | 可追溯；不能根据 UI 默认值补出信号 |
| `JobRecord` | 任务 ID、请求摘要、状态、阶段、截止时间、结果 ID、错误类型 | 取消或失败的旧任务不能发布成新成功结果 |

### 4.3 报告状态分离

- `run_status`：`QUEUED / RUNNING / CANCELLING / SUCCEEDED / FAILED / CANCELLED / TIMED_OUT`。取消受理不等于工作进程已经停止；只有状态机确认后进入终态，终态提交以任务版本检查阻止晚到结果覆盖。
- `evidence_status`：`RESEARCH_ONLY / QUALIFIED / INSUFFICIENT / STALE / INVALID`。
- `action_permission`：`NONE / CONDITIONAL_REFERENCE`。
- 无动作时 `action` 必须为空；界面必须展示原因，不得回退为 HOLD。
- `SUCCEEDED + RESEARCH_ONLY + NONE` 是正常且有价值的结果。
- `SUCCEEDED` 只表示报告任务成功，不表示策略有效或建议成立。

资格判断按策略依赖执行：纯排序策略不强制拥有概率校准；声称概率或按概率决策的策略必须通过概率校准。未使用 Kronos 的已合格基线不必因 Kronos 不可用而停止，但切换必须显式、可追溯，不能悄悄替代。

策略注册另设生命周期：`RESEARCH → SHADOW → ELIGIBLE`，并支持 `SUSPENDED / RETIRED`。历史样本外通过最多进入前瞻模拟观察（SHADOW）；只有前瞻验收通过且资格审批完成，才进入 ELIGIBLE。T22 先完成资格判断和受控验收，不在 T23 之前自动开放日常动作。SHADOW 阶段记录的是模拟决策意图，不是向用户发布的交易动作；其日报仍为 `action_permission=NONE`。数据修订、模型或策略变更须复核受影响的资格，不能仅换 ID 后继续继承。

报告必须声明风险覆盖范围。例如仅覆盖价量、持仓和证券状态时，应说明未覆盖的公告/财务事件风险；尚未接入事件分析不等于该风险为零。

### 4.4 数据质量与缓存政策

- 价格必须是有限、有效数值，并满足 OHLC 关系；坏价格禁止补零进入正式推理。
- 日期必须有序、无重复；区分停牌、源数据缺失和节假日。
- 成交量与成交额使用明确单位；缺失、真实零值和可选字段不可混为一谈。
- 对关键字段缺失，拒绝或降为研究事实展示；不伪造完整数据。
- 保留 `AKShare → BaoStock → 缓存` 降级方向，但返回来源、失败原因和快照质量。
- 合格且覆盖请求截止日的缓存可以使用；文件刚写入不代表数据最新。
- 过期缓存只能用于明确标注的历史查看/回放，不能给出当前动作。
- 缓存是可再生的；用于报告或实验的已引用快照不可被缓存淘汰策略删除。
- 同证券、同日跨源价格或口径冲突超过预定容差时隔离，不静默择优。
- 原始成交价格、调整因子、模型研究价格分别保存；现金分红与价格调整不得重复计收益。

### 4.5 存储与运行目录

建议运行目录由配置显式确定，首次使用显示其真实绝对路径。推荐默认 `%LOCALAPPDATA%/KronosDecision/`，但这仍是待实施行为，不能提前写入现有运行说明。

```text
<runtime-root>/
  config/                 # 用户配置与版本
  cache/                  # 可再生 CSV 缓存
  snapshots/              # 已引用的 CSV 数据与清单
  reports/                # 不可变报告与必要模型产物
  research/               # 实验协议、证据与可重放记录
  state/app.sqlite3       # 任务、索引、持仓与资格记录
  logs/                   # 脱敏诊断日志
  backups/                # 用户明确创建的备份
```

- 行情存储继续 CSV，不把 SQLite 元数据称为行情缓存迁移。
- SQLite 引用文件前必须确认文件完整且哈希匹配；失败和孤儿产物可清理，但不得误删已引用快照。
- 文件使用同目录临时写入、关闭句柄、校验后原子替换；Windows 文件占用失败必须保留旧版本。
- 旧 `data/cache/` 和旧配置仅可由显式导入流程复制，不直接移动或删除；导入失败不破坏旧工程。
- 持仓、财务记录、模型访问令牌和日志不得进入仓库、公开报告或第三方 LLM。

## 5. 策略研究与科学验证协议

### 5.1 先冻结研究问题

每个实验在运行前声明：证券范围、主周期、决策时点、特征、候选模型、模型来源、标签定义、股票池版本、成交假设、基准、成本、主指标和允许尝试的参数集合。

首个问题建议为：在相同股票池、持有/调仓规则和费用下，Kronos 是否比简单动量/趋势基线提供稳定的额外排序或风险改善？

预测终点收益、路径均值分数、首次触发条件和可执行交易收益是不同对象，必须分别命名，不能把模型路径均值称为真实可实现收益。

### 5.2 基线顺序

1. 预测层：不变价格/历史均值等低成本基线。
2. 组合层：指数或同池等权持有。
3. 信号层：一个固定的动量/趋势基线。
4. 需要时增加一个简单统计或机器学习基线；新增依赖先做局部选型。
5. 相同策略骨架下加入冻结 Kronos；证明收益后才评估微调。

不同时开放大量指标、模型和自动调参器；所有失败实验也保留记录。

### 5.3 时间切分与来源风险

- 使用扩展窗或滚动窗；训练、校准/调参、最终测试按时间隔离。
- 按最大标签跨度处理跨边界样本；可以共享已经发生的历史上下文，但不能共享未来标签。
- 归一化、缺失处理、阈值、特征筛选和校准器均只拟合在当时可见样本上。
- 同一最终测试窗口不反复用于选型；重新调参后，原测试结果转为开发证据。
- 历史股票池、退市证券和公司行动必须有时点证据；无法获得时明确缩小结论。
- 论文与作者答复的预训练截止口径不同；记录不确定性，不直接指控泄漏，也不宣称已证明公开权重历史无污染。[10][11]
- 固定模型与 tokenizer revision。冻结版本后的前瞻记录提供更强的时间隔离证据。

### 5.4 A 股成交仿真底线

- 收盘后生成的结果，最早在后续适用交易时点模拟执行；不能按同一收盘价成交。
- 股票 T+1、现金和可卖数量正确，禁止无授权卖空或负现金。
- 涨跌停、停牌、上市初期和板块差异按生效规则处理，不用统一常数覆盖所有证券。
- 申报数量、尾数卖出和价格最小变动单位由规则表决定，不将所有股票统一为同一手数规则。
- 佣金、最低收费、税费和过户费用按日期和买卖方向处理；滑点与冲击另行建模。
- 现金与费用账本使用明确精度的定点或 Decimal 计算，并版本化舍入规则；模型特征的浮点数不能直接充当账务金额精度契约。
- 公司行动、分红、拆并股、配股、退市按已支持范围处理；未知事件使相关实验不合格。
- 不能用预测价格填补缺失的真实成交价，也不能用随后一整天成交量当作开盘前已知信息。
- 日线不能确定排队成交或盘中先后顺序；使用预注册保守规则或标记不可判断，不能伪造精细成交。
- 交易规则有历史版本，规则更新不改变旧实验已使用的规则快照。[12]

### 5.5 指标与资格

| 目的 | 主要证据 |
| --- | --- |
| 排序增量 | 每日横截面 RankIC、分组收益、分市场时期表现 |
| 策略效用 | 扣费后相对基线的增量表现、回撤、换手、风险暴露 |
| 概率质量 | Brier、可靠性图、分位数/区间覆盖率；仅对概率功能要求 |
| 可执行性 | 拒单和未成交原因、流动性、成本压力下结果 |
| 稳健性 | 时间分块置信区间、子时期一致性、参数敏感性、不同随机种子 |
| 工程可靠性 | 数据完整性、任务失败、重试、超时、复现与审计 |

- 论文中价格序列的相关性指标不能直接冒充每日横截面选股指标。[10]
- 同日股票与重叠预测不是独立样本；评估应按日期/时间块保留相关结构。
- 主指标和可接受风险预算须在解封测试集前确定；未确定时只能运行研究，不开放动作参考。
- 不预设收益承诺或随意写入“达到某个 Sharpe 即成功”。
- 结论分为：有支持证据、无明显增益、证据不足、实验无效；后三者不是可以忽略的失败日志。
- 研究资格绑定具体数据范围、策略/模型版本、参数、风险政策及复核条件，不是永久通行证。

### 5.6 真正的模型分布与校准

- 增加保留原始模型样本的接口；旧平均接口行为在兼容测试中保持。
- 样本保存或确定性再生成方案必须可审计，不能从平均路径反推分布。
- 采样比例先称“模型采样频率”；温度、top-p 等变化视为分布版本变化。
- 校准器只在独立历史校准窗口拟合，随后在未来测试窗口验证。
- 样本量或尾部支持不足时，不展示伪精确概率和尾部风险；少量样本不是充分的尾部风险估计。
- 真实采样仍可能整体错误，不能用样本集中程度替代预测正确性。
- 非法 OHLC、非有限值或异常输出按版本化规则拒绝/标记；若修正输出，必须重新评估其影响，不能悄悄裁剪后沿用旧资格。

## 6. 复用与依赖决策

### 6.1 总体决策

- **现有工程：使用并扩展。** 不重新实现已有模型或先换 UI。
- **Qlib：有条件使用并扩展研究层。** 已有入口是基础，但示例不是完成品。[8]
- **应用层：不因为研究工具而引入整套重型依赖。**
- **A 股规则和证据门禁：仅对复用缺口进行局部实现，不自建通用量化平台。**

### 6.2 Qlib 依赖例外（D01，尚未批准）

现有规范禁止 pyarrow；Qlib 的依赖包含 pyarrow。[7][9]

推荐将约束明确为：行情缓存仍为 CSV；日常应用不依赖 pyarrow；经用户批准后，独立研究环境可安装 Qlib 所需依赖。研究环境与应用通过快照清单、CSV 和结构化结果交换，不共享可执行对象或不可信 pickle。

若用户不同意：暂停直接集成 Qlib，保留研究协议和数据契约；对轻量候选重新进行有范围的复用验证。不得用 `--no-deps`、静默删依赖或临时自建完整引擎绕过决策。

### 6.3 依赖与维护规则

- 建立唯一运行依赖定义和可复现锁定结果；CPU/GPU 差异显式记录。
- 两份现有 requirements 若保留，应成为同一依赖定义生成的兼容入口，不独立漂移。
- 继续兼容 Conda 使用习惯，但不假设当前机器存在旧的 `kronos` 环境。
- 不在普通启动时自动 pip 安装或升级依赖。
- 新框架只有完成隔离环境安装、核心路径和反例验证后，才能从候选证据升级为已验证依赖。
- 研究框架自带数据不自动满足时点、完整性或商业许可要求；数据单独验收。

## 9. 版本兼容、迁移与回退

### 9.1 渐进迁移

1. 先给旧界面增加明确的无动作/研究状态，再替换核心流水线。
2. 新报告使用显式 `schema_version`；新旧 API 不能依赖页面猜测格式。
3. 历史报告只读保留；必要时使用展示适配，不重新计算后冒充原报告。
4. 旧缓存和配置导入前展示源路径、目标路径、影响范围与备份位置；不自动覆盖。
5. 不支持的数据库或报告版本安全拒绝，不做隐式破坏性降级。
6. 新旧路径可以对同一快照做离线对照，但旧策略不因此恢复动作资格。

### 9.2 恢复机制

- 配置：保留上一有效版本；写入失败不改变运行快照。
- 行情：重新抓取可再生缓存；已引用快照通过备份恢复，不删除历史证据。
- SQLite：使用一致性备份方式；不可直接把运行中的单个数据库文件当完整备份。
- 模型：切回已验证版本或停止相关策略；禁止用模拟模型伪装可用。
- 任务：失败/取消是终态；恢复或重试创建可追溯的新执行记录，不重复发布。
- 研究结果：更正通过新版本和失效标记表达，不覆盖原实验。
- 发布包：保留上一程序版本及对应依赖；数据 schema 不可逆时不能宣称代码回退等于完整恢复。

## 11. 工作组织、进度与成本控制

### 11.1 关键路径

- 先串行稳定数据和报告契约，再扩大并行。
- 研究框架选择、数据时点和交易账务是研究有效性的关键路径，不能由 UI 进度掩盖。
- 基线闭环早于 Kronos 微调，真实样本接口早于概率校准，资格检查早于动作展示。
- 持仓能力可在公共存储契约稳定后与部分模型研究并行，但不能并发修改共同契约文件。

### 11.2 允许的短任务并行

- 契约冻结后，数据适配测试与报告静态页面可并行，分别限定文件。
- 回测规则审核与模型样本接口可并行，主代理独立集成和验收。
- 纯文档、已落地行为核对与已实现功能验证可并行。
- 子代理不得自行更换模型、框架、数据授权、研究目标或验收政策。

### 11.3 进度汇报格式

每个任务汇报：实际改动、实际命令/退出码、产物或运行 ID、已验证/部分验证/未验证项、阻塞及下一项。区分“进程仍运行”与“产生新证据”，不以耗时推断进展。

本轮不估计虚假的人日或收益目标。M0 测量环境与基线后，再按关键路径给出分批工期；数据授权等待和前瞻观察时间不能压缩成编码工期。

### 11.4 资源控制

- 先用基础数据质量和低成本因子筛选，再对有限范围运行模型。
- 推理缓存键包含输入快照、模型/tokenizer revision、周期、参数、种子与实现版本。
- 批量样本数由精度与资源试验确定，不盲目把更多样本等同更准确的风险概率。
- 冻结实验数量和参数搜索预算；增加试验前记录理由，防止不断试到偶然好结果。
- 所有真实数据、公开模型下载和远程服务请求遵循来源许可及速率限制。

## 12. 交付定义与停止条件

### 12.1 三种清楚区分的交付物

1. **可靠研究版：** M0～M3 的工程和研究闭环可用；输出事实与研究，不宣称有合格交易动作。
2. **模型评估版：** M4 完成，明确 Kronos 的保留/降级/停用结论；即使结果不理想也可以完成交付。
3. **条件化决策辅助版：** M5 的工程与前瞻资格验收完成，只有通过的策略在通过的范围内开放参考。

没有合格策略时，可以交付可靠研究版；不能把它改名为已完成的条件化决策辅助版。未获用户授权，不发布、部署或推送。

### 12.2 每阶段停止条件

- 该阶段选定验收项证据充分；
- 没有阻断当前交付能力的问题；
- 剩余限制和未验证项已显式记录；
- 没有因为追求保险无限增加指标、测试、框架和重构。

如果同一路径连续失败两次，先区分代码、环境、权限、数据或工具问题，再换路径或报告阻塞。不因期限压力用模拟行情、预测成交价或杜撰测试输出补齐证据。

### 12.3 下一次实施的最小授权单元

建议首先只授权 **M0（T01～T03）**，验收“测试隔离、无证据动作阻断、安全启动”。完成后根据实测环境、差异和真实证据，细化 M1 的执行批次，不一次性授权所有研究和外部数据操作。
